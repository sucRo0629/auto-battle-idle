# Class Philosophy

この文書は、現在の職群がなぜこの分割になっているのかを整理する設計思想メモである。

個別スキル、数値、習得レベル、JSON スキーマは [spec/classes-and-skills.md](spec/classes-and-skills.md) を正本とする。戦闘全体の Kill / Flow / Survival 構造は [combat-architecture.md](combat-architecture.md) を参照する。

ここではクラス仕様ではなく、職群の上位構造を扱う。

## 1. この文書で扱う三分類

各ロールまたは職群は、基本的に **基礎 / 発展 / 変則** の 3 職構成として読める。

[spec/classes-and-skills.md](spec/classes-and-skills.md) では「基礎 / 拡張 / 変則」と表記されている箇所がある。この文書では、ユーザー向けの設計思想として「発展」を用いるが、意味は同 spec の「拡張」と同じである。

### 基礎

基礎は、そのロールまたは職群の基本機能を最も純粋に実現する職である。

数値的に弱い初期職という意味ではない。基礎職は、その職群が何を担当しているかを最も分かりやすく示す基準線である。

- ディフェンダーなら、前線を受け止める。
- ファイターなら、近接で敵を処理する。
- シューターなら、遠隔物理として攻撃回数を火力へ変える。
- キャスターなら、魔法出力を安定して供給する。
- Survival 主軸なら、欠損 HP や被害状態を処理して継戦を成立させる。

### 発展

発展は、基礎職が持つロール本来の機能を維持しながら、別のシステム要素を追加する職である。

重要なのは、基礎機能を捨てない点である。発展職はロール外へ逸脱するのではなく、同じ目的をより複雑な条件、対象、時間構造で実現する。

- 護法士は、防御を単体の硬さから戦線全体の安定へ広げる。
- 双刃士は、近接処理を Hit 数とコンボ加速へ広げる。
- 弩砲士は、遠隔射撃を溜めと貫通ラインへ広げる。
- 印術師は、魔法火力を条件分岐と対象構造の最適化へ広げる。
- 結界師は、回復の後処理をバリアや軽減による事前猶予へ広げる。

### 変則

変則は、ロールの基本機能から一歩離れ、戦場全体への影響を担当する職である。

変則職は「基礎職の別味」ではない。多くの場合、敵 HP を直接削る、被害を受ける、HP を戻すといったロールの直線的な目的から離れ、戦闘が成立する条件そのものへ干渉する。

[combat-architecture.md](combat-architecture.md) の整理では、槍術士・狩猟士・法陣師は Flow Layer として扱われる。これは、変則が単なる補助や支援ではなく、位置、局所条件、時間密度、ダメージ流量といった戦場構造を操作するためである。

## 2. なぜ 3 職構成なのか

3 職構成は、同じロール内に「標準」「強化版」「変わり種」を置くためだけの数合わせではない。

このプロジェクトでは、1 つのロールを 3 つの視点へ分解している。

1. そのロールの核は何か。
2. その核を維持したまま、どの戦闘システムへ接続できるか。
3. そのロールから離れたとき、戦場全体のどの条件を操作できるか。

このため、基礎 / 発展 / 変則は強さの段階ではない。設計上の距離である。

- 基礎は、ロールの中心にいる。
- 発展は、中心を保ったまま別システムを取り込む。
- 変則は、中心から外へ出て戦場条件を扱う。

この構造により、同じロール内の差分を単なる DPS、耐久、回復量の大小にしない。各職は「何を操作しているか」で分かれる。

## 3. ディフェンダー

ディフェンダーは「味方を守り、戦線を維持するロール」である。ただし、防御を単なる硬さではなく **防御対象の違い** で分解している。

### 鉄衛士 → 護法士 → 闘技士

鉄衛士は、ディフェンダーの基礎である。

鉄衛士が作るのは、単一路線を受け止める物理ラインである。「ここは抜かれない」という前線そのものを担当し、ディフェンダーの最も純粋な機能を示す。

護法士は、その防御を戦線全体へ広げる発展職である。

鉄衛士が一点の前線を作るのに対し、護法士は範囲攻撃、魔法ダメージ、前衛 Kill / Flow クラスの被害などを含めた崩壊リスクを吸収する。ここで拡張されているのは、受け止める対象である。単体の正面受けから、パーティ全体の安定へ広がっている。

護法士は、Guardian のようにすべての攻撃を一点で受け切る職ではない。護法士が作る安定性は、front の他ユニットを sub-defender 化し、前衛全体で被害を分担できる状態を作ることにある。

闘技士は、ディフェンダーの変則職である。

闘技士は被弾を単なる損失として扱わず、拘束、反撃、制圧へ変換する。ここで変質しているのは、防御の目的である。鉄衛士と護法士が「崩れないこと」を中心に置くのに対し、闘技士は「殴られることで戦況を変える」方向へ踏み出している。

闘技士は main tank の代替ではない。単体ターゲット固定へ変換するよりも、counter、stun、knockback などの局所制圧へ変換することが本質である。そのため、闘技士は「常時最も狙われ続けるディフェンダー」ではなく、「狙われた局面を制圧へ返すディフェンダー」として扱う（`arenaDominance` 中のみ単体固定の例外あり。[combat.md](spec/combat.md)）。

ディフェンダーの三分類は、次のように整理できる。

- 基礎: 鉄衛士は、単一路線の被害を受け止めて前線を作る。
- 発展: 護法士は、防御対象を戦線全体へ広げて崩壊リスクを下げる。
- 変則: 闘技士は、被弾を起点に敵の行動や局所戦闘を制圧する。

したがって、ディフェンダーの変化は「硬さが増える」ではなく、**被害の受け口が、点から面へ、さらに制圧行動へ変わる** こととして読める。

## 4. ファイター

ファイターは、近接で敵の処理対象を担当する物理職群である。

近接であること自体よりも、敵をどう処理するか、攻撃イベントをどう発生させるかが主軸になる。

### 剣術士 → 双刃士 → 槍術士

剣術士は、ファイターの基礎である。

高 DEF の単体敵を安定して処理する標準単体処理職であり、近接物理が担う「敵を正面から確実に処理する」機能を最も純粋に示す。

双刃士は、近接処理を Hit 数とコンボ加速へ発展させる。

剣術士が安定した単体処理を担うのに対し、双刃士は瀕死敵への Hit 密度とフィニッシュ速度を高める。ここで追加されるのは、攻撃イベントの時間密度である。近接物理の目的は維持しながら、処理方法が「一撃の安定」から「連撃の密度」へ変わる。

双刃士の移動は「前線保持」ではなく「一時侵入」である。背後侵入、瀕死敵への差し込み、短時間の高密度 hit は Kill の成立条件であり、その場に留まったこと自体を Defender 的な受け口化とはみなさない。双刃士は「前に出たから tank になる」職ではなく、「処理対象へ短時間アクセスして戻る、または背後に留まって処理を続ける」高速処理職として扱う。

槍術士は、ファイターの変則職である。

槍術士は特定の敵を処理対象として持たず、接敵領域、前線圧力、位置による戦闘条件を操作する。近接職でありながら、主目的は敵 HP の処理ではなく「どこで戦うか」を整える Position Flow である。

ファイターの変化は、次のように読める。

- 基礎: 剣術士は、近接物理の標準単体処理を担当する。
- 発展: 双刃士は、Hit 数とコンボによって処理速度を高める。
- 変則: 槍術士は、処理対象から離れて前線の位置と圧力を操作する。

つまり、ファイターは **対象処理 → イベント密度 → 接敵条件** へ広がる職群である。

## 5. シューター

シューターは、射撃という行為の時間構造を火力へ変換する遠隔物理職群である。

単に遠くから攻撃する職ではなく、「撃つ」「待つ」「仕込む」という行動ルール差で分かれる。

### 弓術士 → 弩砲士 → 狩猟士

弓術士は、シューターの基礎である。

攻撃回数と攻撃速度を軸に、遠隔敵を処理する。射撃の基本機能である継続火力と連射構造を最も素直に表す。

弩砲士は、射撃を溜め、重撃、貫通ラインへ発展させる。

弓術士が攻撃回数で火力を積み上げるのに対し、弩砲士は攻撃間隔と一撃の重さを戦術要素にする。ここで追加されるのは、射撃の待機時間と射線構造である。処理対象も遠隔敵から高 Max HP 対象や貫通ラインへ変わる。

狩猟士は、シューターの変則職である。

狩猟士は直接的な撃破性能ではなく、視界妨害、罠、範囲 DoT、DoT 時間密度によって敵の行動精度と戦闘テンポを崩す。これは Field / Time Flow であり、射撃職でありながら主に局所戦場を操作する。

シューターの変化は、次のように読める。

- 基礎: 弓術士は、攻撃回数と連射で遠隔物理の継続火力を作る。
- 発展: 弩砲士は、溜めと貫通によって射撃の時間と射線を重くする。
- 変則: 狩猟士は、罠や妨害で局所戦場と戦闘テンポを制御する。

つまり、シューターは **連射 → 重撃 → 局所制圧** へ広がる職群である。

## 6. キャスター

キャスターは、魔法によって戦場の出力、流れ、意味を操作する職群である。

魔法職の差分は、物理と別のダメージタイプを持つことだけではない。魔法出力をそのまま出すのか、条件で最適化するのか、戦場構造そのものへ広げるのかで分かれる。

### 魔術師 → 印術師 → 法陣師

魔術師は、キャスターの基礎である。

状況依存の少ない魔法ダメージを安定して供給し、キャスター火力の基準線になる。戦場ルールを変えず、魔力をそのまま火力へ変換する。

印術師は、魔法火力を条件分岐と対象構造の最適化へ発展させる。

魔術師が固定出力であるのに対し、印術師は対象数、HP 割合、隊列などの戦術情報に応じて攻撃効果を有利な形へ切り替える。ここで追加されるのは、火力の量ではなく当て方と効率である。戦場ルールを変えるわけではないため、これは Flow ではなく Structured Kill として扱われる。印は **乾印と坤印の 2 種**（Wind / Earth Branch に対応）であり、味方への付与ではなく、攻撃単位に組み込まれる条件式として扱う。

法陣師は、キャスターの変則職である。

法陣師は魔法職でありながら、主所属は Kill ではなく Flow として読むのが自然である。扱う対象が魔法ダメージ量ではなく、ダメージ流量、集中、分配、転送といった戦場構造だからである。

キャスターの変化は、次のように読める。

- 基礎: 魔術師は、状況依存の少ない基準魔法火力を担当する。
- 発展: 印術師は、条件分岐で攻撃効果と対象構造を最適化する。
- 変則: 法陣師は、ダメージ流量を再配置して戦場全体の効率を変える。

つまり、キャスターは **固定出力 → 条件適応 → 構造操作** へ広がる職群である。

## 7. Survival 主軸クラス

この節は `sp_` クラス群を、UI 上のロール名ではなく Survival Layer の操作点として整理する。

Survival 主軸クラスは、味方の戦闘継続能力を維持する。[combat-architecture.md](combat-architecture.md) の Survival Layer では、Defense Control が被害の入口を設計し、Recovery / Stability / Sustain Control が受けた損失を戦闘継続可能な状態へ戻す。

### 療養師 → 結界師 → 薬草師

療養師は、Recovery Control の基礎として読める。

直接 heal によって欠損 HP を戻し、余剰回復をバリアへ変換する。損失が発生した後に、それを継戦可能な状態へ戻す Recovery の中心である。上位個性は sustain ではなく **崩壊後の即応復元** に置き、大きな被害を受けた味方を即座に立て直す方向で読むのが自然である。

結界師は、回復をバリアと軽減へ発展させる職として読める。

療養師が欠損後の回復を主軸にするのに対し、結界師はバリアやダメージ軽減によって、崩壊前に猶予を作る。ここで追加されるのは、損失が確定する前の安定化である。直接 heal は保護を成立させる補助であり、役割の本体は **崩壊前猶予の作成** にある。

薬草師は、Sustain / Dispel Control へ寄せた変則として読める。

薬草師は HoT、DEF buff、debuff / DoT 対策によって長期戦を支える。現行設計では近接帯に置かれ、instant / burst heal は療養師・結界師より意図的に低い。これは純粋な回復量よりも、持続、状態異常対策、局所的な戦線維持へ寄せた設計として読める。近接帯配置の主理由は、戦場制御ではなく **Survival 主軸内での射程個性の分離** と、薬草師というフレーバーを長射程 caster 系から外すことにある。

Survival 主軸クラスの整理は、次のようになる。

- 基礎: 療養師は、欠損 HP を戻し、崩壊後の損失を即座に回収する Recovery を担当する。
- 発展: 結界師は、バリアと軽減で崩壊前の猶予を作る。
- 変則: 薬草師は、HoT、DEF buff、debuff / DoT 対策で長期戦を支える。

特に薬草師は、狩猟士との差分として「毒 DoT ではなく HoT sustain と敵 `atk` debuff」を持つ整理が既存 spec にある。狩猟士が Flow として局所戦場を制御するのに対し、薬草師は Survival として長期戦維持と状態異常対策を担当する。薬草師の debuff は位置操作や行動テンポ操作ではなく、**被害量・被害速度の抑制** に留まるべきである。

## 8. 上位構造としての読み替え

現在の 15 職は、UI 上のロールだけで見ると次のように見える。

- ディフェンダー 3 職
- Kill / Flow 主軸 9 職
- Survival 主軸 3 職

しかし設計思想としては、次の 3 レイヤーへ再配置すると意図が明確になる。

- Kill: 敵 HP をどう削るか。
- Flow: 戦闘が成立する条件をどう変えるか。
- Survival: 味方が倒れ切るまでの時間をどう延ばすか。

基礎 / 発展 / 変則の三分類は、このレイヤー構造と接続している。

基礎職は、多くの場合その職群の最も直線的な役割を担当する。発展職は、その役割を維持したまま対象、条件、時間構造を増やす。変則職は、同じ職群に属しながら Kill / Flow / Survival の境界へ移動し、戦場全体の成立条件を扱う。

このため、変則職は「ロールから外れた例外」ではなく、各職群が戦闘システム全体へ接続するための出口である。

## 9. 今後の設計判断に使う基準

新しいスキルやクラス分岐を設計するときは、まず次を確認する。

1. その変更は、基礎 / 発展 / 変則のどこを強めるのか。
2. その職は、敵 HP、戦場条件、味方生存のどれを主に操作しているのか。
3. 既存職との差分を、数値ではなく操作対象で説明できるか。

この基準で説明できる限り、クラス差分は単なる強弱ではなく、編成の意味として成立する。

逆に、差分が「同じことをより高い数値で行う」だけになる場合、その職は既存職の設計思想と衝突しやすい。

このプロジェクトにおける基礎 / 発展 / 変則とは、強さや習得順ではなく、**ロールの中心から戦場構造へ向かう距離**である。
