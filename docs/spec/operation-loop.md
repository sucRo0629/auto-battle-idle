## 1. 用語（プレイヤー向け）

| 用語 | 意味 |
| ---- | ---- |
| **作戦** | 複数 Wave を通した 1 回の攻略単位 |
| **Wave** | 作戦内の個別戦闘 |
| **初期準備** | Wave 1 開始前の編成・戦闘方式選択・出撃確定 |
| **Wave 間準備** | Wave 2 以降の各 Wave 開始前に行う準備（単なる短い BattlePhase ではない） |
| **作戦結果** | 最終 Wave 終了後の結果画面・恒久反映の境界 |

**採用しない正本用語:** 「ラン」「ローグライク」「ノード」など旧 [roguelike-mode.md](roguelike-mode.md) 由来の呼び方。

内部名称（クラス名・enum・Save キー等）は **R5 実装時に subset 確定**（データ責務は [combat-data-schema-refactor.md](../plans/combat-data-schema-refactor.md)）。

## 2. 上位ループ

```
初期準備
  → Wave 戦闘
  → Wave 終了
  → （最終 Wave でなければ）Wave 間準備
  → 次 Wave 戦闘
  → …
  → 最終 Wave 終了
  → 作戦結果
```

**原則:**

- **Wave 間準備**は編成画面・戦闘方式選択・作戦内状態・リトライを跨ぐ **上位進行状態** として扱う。
- **`BattleEngine` だけで完結させない。** 準備画面は戦闘外のゲーム状態として実装する可能性が高い（[battle-field.md §Wave 作戦と legacy BattlePhase](battle-field.md#wave-作戦と-legacy-battlephase)）。
- Wave 戦闘中は **直接操作なし** を維持（[combat-architecture.md](../combat-architecture.md) §0 と整合）。
- 戦闘速度変更・ポーズの詳細は **R7**。R3 では上位導線のみ [§8](#8-リトライ導線r7-接続) に記載。

## 3. 作戦状態と戦闘状態の分離

作戦状態と戦闘状態を **同じ保存オブジェクトへ無制限に混在させない** ことを原則とする。所有クラス・型・永続化形式は **R4 以降**。

### 3.1 作戦状態（複数 Wave を通して保持）

| 候補フィールド | 内容 |
| -------------- | ---- |
| 現在の作戦 ID | 選択した作戦（旧「ステージ」に相当しうるが 1:1 固定しない） |
| 現在の Wave 番号 / Wave ID | いま挑戦中または準備中の Wave |
| クリア済み Wave | 作戦内で勝利確定した Wave の記録 |
| 現在の編成 | 味方 4 兵科（同一兵科禁止） |
| 各兵科の選択中戦闘方式 | Wave 間で保持。毎 Wave 未選択へ戻さない |
| 取得済み作戦内パッシブ | 作戦終了まで維持（取得 UI・コストは R8 / R11c） |
| 未使用作戦内リソース | 入手量・タイミングは未確定 |
| Wave 開始チェックポイント | [§7](#7-wave-開始チェックポイント) |
| 作戦固有ルール | ステージ / 作戦定義由来の modifier |

### 3.2 戦闘状態（Wave 開始時に生成、Wave 終了時に破棄または初期化）

| 候補フィールド | 内容 |
| -------------- | ---- |
| Combatant | 味方・敵ユニット runtime |
| HP / Barrier | Wave 内の生存・シールド |
| DoT / HoT | 継続効果 |
| CC | 行動制限等 |
| 現在ターゲット | chase / attack 解決結果 |
| 位置（`battleX` 等） | フィールド上配置 |
| Attack timer | 攻撃間隔カウント |
| 一時バフ / デバフ | Wave 内限定 |
| 戦闘内カウンタ | per-Wave フラグ等 |
| 一時オブジェクト | projectile / field 等 |

Wave 開始時: 作戦状態から **編成・戦闘方式・作戦内パッシブ** を戦闘へ反映し、上記戦闘状態を新規構築する。

Wave 終了時: 戦闘状態を確定・破棄し、作戦状態へ **クリア記録・報酬候補** のみを反映する。

## 4. 初期準備（Wave 1 前）

Wave 1 開始前に、最低限次を行える **上位仕様**:

| 項目 | 内容 |
| ---- | ---- |
| 作戦情報の確認 | 作戦名・Wave 数等（開示範囲の詳細は未確定） |
| Wave 1 の敵情報確認 | 敵編成の事前確認 |
| 味方 4 兵科の編成 | 空きスロット不可（出撃時 4 人前提） |
| 同一兵科重複の禁止 | 味方編成全体で 1 兵科 1 体まで |
| 各兵科の戦闘方式選択 | 兵科ごとに 2 方式から 1 つ |
| 出撃確定 | 次状態へ遷移する明示的操作 |

**未確定:** 作戦内パッシブ取得を初期準備でも可能にするか。

**R6 以降（UI Phase）:** 編成・戦闘方式のデフォルト値、出撃ボタン有効条件、初回ガイド、画面レイアウト。

## 5. Wave 戦闘

### 5.1 Wave 開始時の反映

作戦状態 → 戦闘状態へ反映する項目:

| 項目 | 備考 |
| ---- | ---- |
| 現在の編成 | |
| 各兵科の戦闘方式 | |
| 取得済み作戦内パッシブ | R8 で実装 |
| Wave 固有の敵編成 | |
| Wave 固有ルール | ステージ / Wave 定義 |

敵側の **戦闘方式・所持パッシブ** も Wave 開始時に戦闘へ反映するが、**データ構造は R4** へ送る。

### 5.2 戦闘中

- 直接操作なし。観察用の **一時停止** と **倍速（最小 UI）** は [battle-field.md §8.11](battle-field.md#8111-戦闘一時停止観察-ui--phase-4-task-1) / [§8.11.1a](battle-field.md#8111a-戦闘倍速最小-ui--r7b) 参照（R7b）。
- 座標・接敵・描画は [battle-field.md](battle-field.md) の戦闘フィールド節（legacy BattlePhase 含む）が現行実装説明。新ループ置換後も **1 Wave 内の戦闘 sim** として再利用する想定。

### 5.3 Wave 終了判定

最低限、次を **区別** する:

| 結果 | 概要 |
| ---- | ---- |
| **Wave 勝利** | 当該 Wave の勝利条件達成（[§5.3.1](#531-wave-勝利条件r12a)） |
| **Wave 敗北** | 当該 Wave の敗北条件達成 |
| **timeout / 異常終了** | 時間切れ・内部エラー等（扱いは未確定） |
| **最終 Wave 勝利** | 作戦内最後の Wave をクリア |

#### 5.3.1 Wave 勝利条件（R12a）

**Wave の勝利条件は敵全滅で固定する。**

これは **ゲームルール** であり、[§15 敵問題](#15-敵問題と戦術目標r12a) ではない。敵問題は勝利条件そのものを定義せず、勝利条件の達成過程でプレイヤーへ戦術課題を提示する。

#### Wave 勝利時

1. 戦闘 sim を停止
2. 戦闘状態を確定
3. 作戦状態へ Wave クリアを記録
4. 報酬・作戦内リソースの反映（**入手量・タイミングは未確定**）
5. 最終 Wave でなければ **Wave 間準備** へ
6. 最終 Wave なら **作戦結果** へ

#### Wave 敗北時

- **作戦全体を即終了させない**
- 現在 Wave の **再試行導線** を持つ（[§8](#8-リトライ導線r7-接続)）
- Wave 開始前の準備状態へ戻れる
- 作戦開始からのやり直しも可能

敗北時の自動遷移先は **R7 リトライ仕様** と接続できる形にしておく（確認ダイアログなし方針を維持）。

Wave 2 以降の各 Wave 開始前に入る **上位状態**。BattlePhase の 1 フェーズとして短く済ませない。

### 6.1 将来扱う項目（R3 では UI 未確定）

| 項目 | 備考 |
| ---- | ---- |
| 次 Wave の敵情報確認 | 開示範囲は未確定 |
| 編成変更 | |
| 戦闘方式変更 | 前 Wave から **そのまま保持**。ここで変更可能 |
| 作戦内パッシブ取得 | **R8 / R11b**。直接指定。候補は作戦専用 ID |
| 未使用リソース確認 | |
| 出撃確定 | Wave 開始チェックポイント更新の境界 |
| 現在 Wave の再試行 | [§8](#8-リトライ導線r7-接続) |
| 作戦最初からの再開始 | [§8](#8-リトライ導線r7-接続) |

### 6.2 R3 で明示する禁止・方針

| 禁止 / 方針 | 理由 |
| ----------- | ---- |
| Wave 間準備に入っただけでパッシブを **自動取得しない** | プレイヤー直接指定方針 |
| **ランダム 3 択報酬を表示しない** | 旧 roguelike 報酬を採用しない |
| 作戦内パッシブ実装本体は **R8** | |
| **R6 最小 Wave 間準備** | 編成変更 + 戦闘方式変更だけで成立可能にする |

### 6.3 作戦内リソースとパッシブ取得コスト（R11c）

`data/operation-passive-catalog.json` が正本。

| 原則 | 内容 |
| ---- | ---- |
| 取得上限なし | 同じスロットへ候補を重複なく追加できる限り、取得回数に hard cap は無い |
| コスト式 | `cost = base(unlockLevel) + n × sameClassStackStep`（`n` = 取得前の同一スロット取得数） |
| unlockLevel | **コスト帯のみ**（パーティ Lv ゲートではない）。`costUnlockLevelByPassiveId` → `unlockLevelCostTable` |
| 新仕様 Stage の準備時付与 | 各 `waves[].prepResourceGrant`。その Wave の準備開始時に一度付与（[§6.4](#64-wave-準備資源r12h)） |
| legacy 付与 | `waves[].prepResourceGrant` 未指定の既存 Stage では、Wave 2 以降に `waveClearResourceGrant` を fallback として使用 |
| フォールバック | 候補の unlockLevel 欠損時は `passiveAcquireCost` |

実装: `src/game/operationPassiveAcquireCost.ts` / `GameSession.tryAcquireOperationPassive`。

### 6.4 Wave 準備資源（R12h）

作戦ポイントの付与は「完了した Wave へのクリア報酬」ではなく、**次に開始する Wave の準備資源**として扱う。新仕様 Stage では各 Wave が `prepResourceGrant` を所有する。

```json
{
  "waves": [
    {
      "prepResourceGrant": 0,
      "enemyGroups": []
    }
  ]
}
```

| 項目 | 契約 |
| ---- | ---- |
| 型 | `waves[].prepResourceGrant`。0 以上の整数。乱数は使用しない |
| 所有 | 対象 Wave 自身が固定値を持つ。Stage 直下の別配列には分離しない |
| 付与時点 | 対象 Wave の準備開始時に一度だけ加算する |
| Wave 1 | `prepResourceGrant > 0` なら戦闘開始前に Wave 準備画面を開いて付与する。明示的な `0` なら現行どおり出撃前編成から戦闘へ進む |
| Wave 2 以降 | 付与量が `0` でも Wave 間準備画面を開く。新規付与がなくても持ち越しポイントを使用できる |
| 最終 Wave 後 | 次 Wave がないため付与しない |
| 二重付与防止 | retry、画面再表示、formation との往復、checkpoint 復帰で同じ Wave の grant を再加算しない |
| 持ち越し | 未使用ポイントは次 Wave へ持ち越す |
| パッシブ取得 UI | 表示可否を `prepResourceGrant > 0` だけで決めない。候補の有無・所持ポイント・取得コストから表示と取得可否を判定する |

`prepResourceGrant` の **未指定** と明示的な `0` は区別する。新仕様 Stage は Wave 値を正とする。未指定の legacy Stage は、Wave 1 では従来どおり付与なし、Wave 2 以降では `operation-passive-catalog.json` の `waveClearResourceGrant` を fallback として使用する。全 Stage 移行後の legacy field と fallback の削除は別 cleanup とし、R12h では先行削除しない。

この構造は、Wave 1 前に構築して挑む高難度 1 Wave Stage、Wave ごとに配分量が異なる Stage、新規付与なしで持ち越しだけを使う Wave、長期 Stage の小刻みな配布を固定データで表現できる。将来のローグライク展開は妨げないが、R12h ではランダム生成・ランダム報酬を導入しない。

**Phase 境界:** R12h は schema、validation、runtime 接続、Wave 1 開始前を含む準備遷移、二重付与防止、legacy fallback、authoring、test、試作 Stage への構造入力を扱う。各 Wave の具体的な付与量、取得コスト、`stackStep`、scale、基礎 stat、CombatModule 数値の本調整は **R12i**。

| 項目 |

### 7.3 HP 全回復の採否（R3 確定）

**採用:** 各 Wave を **独立した編成問題** として扱うため、Wave 終了（または次 Wave 開始）時に **HP は全回復** する。

- 前 Wave の損耗を持ち越す **長期消耗戦** にはしない。
- 作戦を通した成長・判断は **作戦内パッシブ** と **未使用リソース** で表現する。

**戦闘方式:** 次 Wave へ **そのまま保持** する。毎 Wave 未選択へ戻さない。変更は Wave 間準備（または初期準備）で行う。

## 8. Wave 開始チェックポイント

現在 Wave を **準備段階から再試行** するため、**Wave 開始直前**（出撃確定時点）の作戦状態をチェックポイントとする。

### 8.1 チェックポイントに含める候補

| 項目 |
| ---- |
| 現在 Wave |
| 編成 |
| 戦闘方式 |
| 取得済みパッシブ |
| 未使用リソース |
| クリア済み Wave |
| Wave 開始前に確定した取得・消費 |

### 8.2 再試行時の原則

| 原則 | 内容 |
| ---- | ---- |
| 戦闘中の変化は破棄 | 敗北時に HP・DoT 等を作戦状態へ書き戻さない |
| チェックポイントを復元 | 出撃確定時点の作戦状態へ |
| 遷移先 | Wave 間準備、または出撃直前 |
| 過去 Wave | **再戦しない**（クリア済み Wave は維持） |

### 8.3 パッシブ・リソースの巻き戻し（R3 確定）

**推奨を正本化:** チェックポイントは **出撃確定時点**。

- 出撃 **前** に行ったパッシブ取得・リソース消費は、Wave 敗北後の再試行でも **維持** する。
- Wave **戦闘中** に得たものは再試行で破棄（戦闘状態側）。
- 別の取得に変更したい場合の **取り消し・再購入** は **R8** へ送る。

具体的なコピー方式・永続化・メモリ表現は **R4 以降**。

## 9. リトライ導線（R7 接続）

R7 で実装する 3 種類 + 作戦中断。作戦状態・チェックポイントと整合させる。

**到達可能な入口:** 敗北 retry overlay・**戦闘ポーズ銘板（Wave 戦闘中）**・Wave 間準備。

| 種類 | 挙動 | チェックポイント |
| ---- | ---- | ---------------- |
| **同じ設定で再戦** | 現在 Wave を同じ編成・同じ戦闘方式・同じパッシブで **即再戦** | Wave 開始チェックポイントを使用 |
| **準備へ戻る** | 現在 Wave の準備へ。編成・戦闘方式を変更可能 | クリア済み Wave は維持。パッシブ変更可否は R8 |
| **作戦を最初から** | Wave 1 前の **初期準備** へ。作戦内パッシブ・リソース・クリア済み Wave を初期化 | 恒久解禁・作戦外記録は消さない |
| **ステージ選択へ** | 未完了 Operation を **破棄** し `stageSelect` へ | checkpoint 破棄。`currentStageId` は維持 |

- Wave **戦闘中**もポーズから上記へ入れる（敗北を待たない）。
- **確認ダイアログを挟まない** 方針を維持。
- UI 上のボタン名は未確定。

## 10. 作戦完了（最終 Wave 勝利）

| 手順 | 内容 |
| ---- | ---- |
| 1 | 作戦クリアを記録（作戦外進行へ反映する候補） |
| 2 | 作戦内状態を終了 |
| 3 | **作戦結果** へ遷移（verify OFF: battle 上の最小 overlay。verify ON: 非表示・従来 loop） |
| 4 | 作戦内パッシブ・未使用リソースは **破棄** |
| 5 | 恒久的なクリア記録・兵科解禁等があれば **作戦外進行** へ反映（結果 UI **表示前** に適用） |

**R7e 最小 UI（verify OFF）:** `outcome`・`stageId`・`reachedWaveIndex` を表示。操作は **同じステージで再戦**（Wave 0・formation 経由）と **ステージ選択へ**。報酬一覧・スコア・演出は未実装。

## 15. 敵問題と戦術目標（R12a）

反復可能な作戦・Wave を設計するときの **authoring 正本**（用語・最小構造）。1 Wave 単位の成立条件・敵側戦術は [§16](#16-1-wave-単位の敵問題r12b)。複数 Wave を通した作戦全体の敵問題・Wave 間関係は [§17](#17-作戦全体の敵問題r12c)。試作 Stage の具体設計は [§18](#18-試作stageの敵問題r12d)。必要能力の導出は [§19](#19-必要能力対処能力r12e)。実装 API・JSON フィールド名・UI 文言は本節では定義しない。上位の設計思想は [enemy-design-concept.md](../enemy-design-concept.md) / [design-philosophy.md](../design-philosophy.md) を参照し、用語の正本は本書とする。

### 15.1 敵問題

**敵問題**とは、敵編成・敵戦闘方式・Wave 構成によって、プレイヤーへ戦術目標を提示し、その達成方法の選択と代償を考えさせる構造である。

[§5.3.1](#531-wave-勝利条件r12a) の勝利条件（敵全滅）とは別概念である。勝利条件はゲームルールであり、戦術目標ではない。

### 15.2 戦術目標

**戦術目標**とは、Wave 内の敵全滅という勝利条件を達成するために、その敵問題でプレイヤーが解決しなければならない課題である。

| 扱い | 内容 |
| ---- | ---- |
| 設計上の位置づけ | **設計用の内部概念** |
| 通常プレイ | **直接表示しない** |
| 攻略支援 | 同一問題で複数回敗北し試行が停滞した場合、段階的に提示してよい |

### 15.3 戦術目標の最小属性

戦術目標は次の **3 属性** で構成する。

| 属性 | 内容 |
| ---- | ---- |
| **対象** | 何に対して課題が掛かるか |
| **目標状態** | 対象が満たすべき状態。「排除する」「維持する」「突破する」などの動詞は、目標状態を文章化した表現として扱う |
| **期限・成立時点** | いつまでに／どの時点で成立とみなすか。**固有期限がない場合の既定値は Wave クリアまで** |

### 15.4 戦術目標数

- 敵問題は **1 つ以上** の戦術目標を持つ。
- **上限は設けない**。
- 難易度や設計意図に応じて複数持ってよい。

### 15.5 敵問題の 5 要素（二層構造）

5 要素は、**戦術目標単位**と**敵問題全体**の二層で記述する。

各戦術目標に対応して、次を持つ。

1. **戦術目標**
2. **戦術目標未達時の敗北原因**
3. **有効な対処**
4. **対処に伴う代償**
5. **敗因の識別可能性**

### 15.6 敵問題全体が持つもの

敵問題全体では、次を持つ。

- 戦術目標同士の関係
- 支配的敗因
- 対処間競合
- 代償
- 全体としての敗因の識別可能性

### 15.7 敗因の識別可能性

**敗因の識別可能性**とは、プレイヤーが戦闘経過と結果から、満たせなかった戦術目標または支配的敗因について合理的な仮説を立て、次回変更する要素を決め、再挑戦によってその仮説を支持・否定・更新できる性質を指す。

| 含む | 含まない |
| ---- | -------- |
| 推測可能性 | UI 表示そのものではない |
| 検証可能性 | |

## 16. 1 Wave 単位の敵問題（R12b）

本節は [§15](#15-敵問題と戦術目標r12a) の枠組みに沿い、**1 Wave 単位**の敵問題と敵側戦術の抽象構造を定義する。実装 API・JSON・具体クラス能力・実データは定義しない。

### 16.1 戦術目標の成立時点

- 戦術目標は、**Wave 開始時点ですべて成立している**。
- 戦闘途中で新しい戦術目標が追加される構造は、R12b の基本形には含めない。
- 戦闘経過によって支配的敗因や達成状況が変化することはあるが、戦術目標自体が後から新設されるわけではない。

### 16.2 事前予測可能性

戦術目標は、Wave 開始前に提示された敵編成および敵戦闘方式から **合理的に予測可能** でなければならない。

Hensei-Only では、プレイヤーが事前の敵情報を読み、味方編成や戦闘方式を決めるためである。

| 求めること | 求めないこと |
| ---------- | ------------ |
| どのような課題が存在しそうかについて合理的な仮説を立てられること | 事前情報から正しい対処を一意に特定できること |

### 16.3 複数戦術目標の関係

複数の戦術目標は、それぞれ **個別に記述・判定可能** でなければならない。

ただし、実際の戦況では次を通じて相互作用してよい。

- 達成期限
- 敗北原因
- 有効な対処
- 対処に伴う代償
- 支配的敗因の移動

「独立」とは互いに無関係という意味ではなく、各課題の対象・目標状態・期限を個別に説明できることを指す。

### 16.4 敵数の最低条件

1 Wave の敵問題は、**最低 2 体以上** の敵によって構成する。

敵 1 体は、高火力、高耐久、回復、軽減、対象選択などの問題要素を提供できるが、単独では戦術目標を成立させない。敵 1 体だけの Wave は、原則として単純な火力検査または耐久検査に留まるため、R12b の敵問題として扱わない。

敵が 2 体以上存在するだけでは成立条件を満たさない。複数の敵が **敵側戦術** として機能し、プレイヤーの敵全滅を妨げる構造が必要である。

### 16.5 敵側戦術

**敵側戦術**とは、複数の敵要素が役割を組み合わせ、プレイヤーによる Wave 内敵全滅を妨げ、1 つ以上の戦術目標を発生させる構造である。

単なる敵の併置、数値の加算、戦況に影響しない能力の組み合わせは敵側戦術として扱わない。

敵側戦術は、少なくとも次を満たす必要がある。

- 複数の敵要素が組み合わさっている
- 単独配置とは異なる戦況を生む
- プレイヤーへ戦術目標を発生させる
- 放置すると敗北原因につながる
- 関連する対処変更によって戦闘経過が変わる

### 16.6 敵側戦術の基本分類

敵側戦術の基本分類は、次の **3 種** とする。

#### 保護戦術

ある敵要素が、重要な別の敵要素の処理を妨げ、その活動時間を延ばす戦術。

保護手段には、配置、耐久、回復、軽減、対象誘導などを含み得る。

本質は、処理したい重要要素を長く機能させることにある。

#### 分担戦術

複数の敵要素が異なる対応を同時に要求し、プレイヤーの限られた対応力を分散させる戦術。

異なる圧力対象、耐久要求、突破特性、単体処理、多数処理などを同時に要求する構造を含む。

各圧力が個別に無視できず、一方への対応が他方への対応力を実質的に下げる必要がある。

#### 相乗戦術

複数の敵要素が連携し、それぞれを単独で配置した場合には存在しない、または著しく弱い新しい圧力を発生させる戦術。

状態の付与と利用、弱体化と高火力、条件生成と条件特効などを将来的な例として含み得る。

具体的な能力設計は本節では行わない。

### 16.7 敵側戦術数

- 1 Wave は、保護・分担・相乗のいずれかの敵側戦術を、**少なくとも 1 つ** 持たなければならない。
- 複数の敵側戦術を同時に持ってよい。
- 競合する複数圧力を必須とはしない。
- 単一の保護戦術または相乗戦術であっても、戦術目標、対処、代償および敗因の識別可能性が成立するなら、1 Wave の敵問題として認める。
- 敵側戦術の分類が存在するだけでは Wave 成立条件を満たさない。

### 16.8 1 Wave の成立条件

1 Wave の敵問題は、次のすべてを満たさなければならない。

1. Wave 開始前に敵編成と敵戦闘方式が確定している
2. 敵が 2 体以上存在する
3. 敵側戦術が 1 つ以上存在する
4. 事前情報から予測可能な戦術目標が 1 つ以上存在する
5. 各戦術目標に、未達時の敗北原因が存在する
6. プレイヤーの選択によって達成状況を改善できる有効な対処が存在する
7. 有効な対処に、同一 Wave 内で実質的な代償が存在する
8. 関連する対処変更によって、戦術目標の達成状況または敗北過程に観測可能な差が生じる
9. 敗北時に、未達だった戦術目標または支配的敗因について合理的な仮説を立てられる
10. すべての戦術目標を代償なく改善する万能対処だけで解ける構造ではない

### 16.9 対処変更後に必要な結果差

有効な対処へ変更した結果、勝利まで変化することを必須とはしない。

少なくとも次のいずれかが変化すれば、検証可能な差として扱う。

- 戦術目標を達成できるようになる
- 戦術目標の達成時点が早まる
- 支配的敗因の発生が遅れる
- 観測可能な破綻が軽減される
- 最初に破綻する戦術目標が変わる
- 支配的敗因が別の戦術目標へ移る

どの選択でも同じ順序、同じ時点、同じ形で敗北する場合、その対処は有効に機能していない。

### 16.10 R12b で成立しない代表例

次は 1 Wave の敵問題として扱わない。

- 敵 1 体だけの Wave
- 同じ敵を複数並べただけで戦術上の相互作用がない
- 片方の敵が戦況へ実質的に影響しない
- 敵側戦術が名目上存在するだけで、戦術目標を発生させない
- 戦術目標を無視しても通常編成で勝てる
- 正しい対処が存在しない
- 対処を変えても戦闘経過が変わらない
- 代償のない万能対処ですべて解決できる
- 高 HP・高 ATK だけで勝敗を決める
- 敗因候補を絞れず、再挑戦しても仮説を更新できない

### 16.11 後続フェーズで再設計する事項

本章は、1 Wave の敵問題と敵側戦術の抽象構造を定義する。次の具体設計は R12b では確定しない。

- 各クラスが実現する敵側戦術
- 現行 R5 対象クラスとの対応付け
- 将来追加される全クラスの能力
- 敵用 CombatModule
- 作戦内パッシブ
- クラスごとの対象選択や戦闘挙動
- 数値、敵数、HP、ATK、取得コスト
- 実際の Stage・Wave データ

具体的なクラス能力、CombatModule、作戦内パッシブおよび敵データは、**後続フェーズで本章の敵側戦術と Wave 成立条件を満たすよう再設計する**。

敵側戦術の分類採否は、現行クラス能力で実現可能かどうかを根拠としない。

## 17. 作戦全体の敵問題（R12c）

本節は [§15](#15-敵問題と戦術目標r12a) / [§16](#16-1-wave-単位の敵問題r12b) の枠組みに沿い、**複数 Wave を通した 1 作戦**の敵問題と Wave 間関係を定義する。実装 API・JSON・具体クラス能力・数値バランス・実 Stage データは定義しない。

### 17.1 作戦全体の敵問題の定義

**作戦全体の敵問題**とは、各 Wave の敵問題を、**Wave 間関係**によって接続した構造である。

各 Wave が [§16.8](#168-1-wave-の成立条件) の 1 Wave 成立条件を個別に満たしているだけでは不十分である。作戦全体として、Wave をまたぐ判断差が生じなければならない。

| 概念 | 位置づけ |
| ---- | -------- |
| Wave 勝利条件（敵全滅） | ゲームルール（[§5.3.1](#531-wave-勝利条件r12a)） |
| 1 Wave の敵問題 | [§16](#16-1-wave-単位の敵問題r12b) |
| 作戦全体の敵問題 | 本節。Wave 間関係で接続された複数 Wave の構造 |

### 17.2 作戦全体としての成立条件

1 作戦の敵問題は、次のすべてを満たさなければならない。

1. 各 Wave が [§16.8](#168-1-wave-の成立条件) の 1 Wave 成立条件を満たしている
2. Wave 間に [§17.3](#173-wave-間関係) の **継続** / **転換** / **複合** / **対立** のいずれかが **1 種類以上** 存在する（4 種類すべてを必須とはしない）
3. 作戦開始前に開示された全 Wave の敵編成から、作戦全体として何が求められるか **合理的に推測できる**
4. 編成変更または戦闘方式変更を **検討する理由** が存在する
5. 作戦ポイントの **集中** と **分散** に、作戦全体として実質的な **代償** がある
6. Wave ごとに戦術目標が完全転換する構成を採用する場合、それが Wave 間関係として説明できる
7. 通常 Stage の最終 Wave が、過去 Wave で提示した敵側戦術または戦術目標を **統合した複合問題** である（[§17.9](#179-最終-wave-の複合問題)）
8. 作戦失敗時または特定 Wave 失敗時に、**未処理の戦術目標** を識別できる（[§17.10](#1710-敗因の識別)）
9. 全 Stage を同一編成で攻略できる **万能編成** を前提にしていない（[§17.11](#1711-万能編成と作戦内汎用編成)）
10. 特定 Stage 内の全 Wave を同一編成で攻略することを **禁止条件** にしていない
11. Wave 間差が、単なる敵数増加または scale 増加だけで構成されていない
12. 現行クラス能力の制約から、必要な問題構造を縮小していない

### 17.3 Wave 間関係

**Wave 間関係**とは、隣接または作戦全体を通じた Wave 同士の戦術要求のつながりを指す。1 作戦には、少なくとも 1 種類以上の Wave 間関係を含める。4 種類すべてを必須とはしない。

#### 継続

前 Wave で提示した戦術要求、対処方針、または作戦内資源の使い方が、後続 Wave でも **意味を持ち続ける** 関係。

前 Wave で立てた仮説・投資・編成判断が、後続 Wave の準備または戦闘経過に影響し得る。後 Wave が前 Wave の延長として読めるが、同一内容の単純反復ではない。

#### 転換

Wave ごとに、戦術目標または主要な敵側戦術が **別系統へ切り替わる** 関係。

前 Wave と同じ兵科・同じ対処を継続して要求する必要はない。完全転換も、作戦全体の Wave 間関係として位置づける（[§17.8](#178-戦術目標の転換)）。

#### 複合

複数 Wave で提示した戦術要求が、後続 Wave または最終 Wave で **同時に、または相互作用する形で再提示される** 関係。

過去 Wave の敵編成をそのまま合算する意味ではない。過去に学習・推測させた複数の戦術要求を、同時または連動して処理させる構造である。

#### 対立

Wave 間で、前 Wave 向けの最適な準備・資源配分・編成判断が、後 Wave 向けの最適解と **競合する** 関係。

作戦全体の限られた判断枠（編成、戦闘方式、作戦ポイント配分）の中で、一方への対応が他方への対応力を実質的に下げる必要がある。

### 17.4 Wave 数の扱い

- **2 Wave 作戦** と **3 Wave 以上の作戦** で、作戦全体の成立基準そのものは **分けない**。
- 3 Wave 以上は、2 Wave より多くの Wave 間関係・判断・資源配分を扱える **高難度作戦** として扱う。
- Wave 数が多いこと自体を、作戦全体の成立条件には **しない**。

### 17.5 事前開示と推測

- 作戦開始前から、**全 Wave の敵編成** を開示する。
- **戦術目標そのもの** は文章で表示しない（[§15.2](#152-戦術目標)）。
- プレイヤーは敵編成と敵戦闘方式から、各 Wave の戦術目標および Wave 間関係を **推測** する。
- 戦術目標の対処方法を **一意に特定できる必要はない**（[§16.2](#162-事前予測可能性) と同型）。

### 17.6 Wave 間の編成変更

- Wave 間では、味方 **4 枠すべて** を変更できる。
- 編成変更自体に、回数制限・追加コスト・固定枠などを **設けない**。
- 作戦全体の判断差は、編成変更を **制限すること** ではなく、**敵問題** と **作戦ポイント配分** によって生じさせる。

### 17.7 作戦ポイントと集中・分散

作戦ポイントの配分によって、**特定兵科への集中強化** と **複数兵科への分散強化** の代償を作る。

| 扱い | 内容 |
| ---- | ---- |
| 付与タイミング | 各 Wave の準備開始時。新仕様 Stage は `waves[].prepResourceGrant` を使用（[§6.4](#64-wave-準備資源r12h)） |
| 高難度 Stage | Wave 1 の `prepResourceGrant` による **初期作戦ポイント** の配布を許容 |
| 本節で定義しないもの | 具体的な付与量、コスト、`stackStep`、数値バランス（→ **R12i**） |
| 本節で定義しないもの | 具体的なパッシブ内容と能力配分（→ **R12e〜g**） |

本節では、資源が **作戦全体の判断**（どこへ集中し、どこを犠牲にするか）にどう関与するかだけを定義する。

### 17.8 戦術目標の転換

- Wave ごとに、戦術目標が **完全に転換** する構成を許容する。
- 前 Wave と同じ兵科・同じ対処を継続して要求する必要はない。
- 完全転換も **転換** という Wave 間関係として、作戦全体に位置づける。

### 17.9 最終 Wave の複合問題

通常 Stage の最終 Wave は、原則として、過去 Wave で提示した敵側戦術または戦術目標を **統合した複合問題** とする。

| 原則 | 内容 |
| ---- | ---- |
| 禁止 | 単なる敵数増加や数値強化だけで最終 Wave を構成すること |
| 通常 Stage | 上記原則に対する **例外を設けない** |
| スコープ外 | ローグライク等、将来の別モードに関する例外設計 |

**過去 Wave の複合問題** とは、過去 Wave の敵編成をそのまま合算する意味 **ではない**。過去に学習・推測させた複数の戦術要求を、**同時または相互作用する形** で再提示することを指す。

### 17.10 敗因の識別

作戦失敗時または特定 Wave 失敗時に、**どの戦術目標を処理できなかったか** 識別できればよい。

| 扱い | 内容 |
| ---- | ---- |
| 単一原因 | 敗因を単一原因へ **固定する必要はない** |
| 支配的敗因 | 複数の戦術目標がある場合、支配的敗因が途中で **移動してもよい** |
| 根拠 | [§15.7](#157-敗因の識別可能性) / [§16.3](#163-複数戦術目標の関係) |

### 17.11 万能編成と作戦内汎用編成

次の 2 つを **区別** する。

#### 認めないもの（万能編成）

**全 Stage** を同一編成で攻略できる万能編成。

兵科変更や戦闘方式変更をほぼ必要とせず、すべての敵問題を処理できる編成は **成立させない**。

#### 許容するもの（作戦内汎用編成）

**特定 Stage** の全 Wave を同一編成で攻略できる編成。

これは通常の想定解に限定せず、やり込み、縛りプレイ、高度な別解として **許容** する。

したがって、各 Wave で **必ず** 編成変更を要求する必要はない。重要なのは、作戦全体の敵問題に対して **判断と代償** が成立していることである。

### 17.12 Stage 先行設計と後続フェーズ

[R12d](../plans/phase-roadmap.md#r12d--試作-stage-の敵問題設計) では、具体的な兵科能力から Stage を組み立て **ない**。先に次を設計する。

1. 各 Wave の敵問題
2. 各 Wave の敵側戦術
3. 戦術目標
4. Wave 間関係
5. 最終 Wave の複合構造
6. 想定される失敗理由
7. 必要となる判断の種類

その後、**R12e** で必要能力・対処能力を導出する。

#### 現行能力の扱い

- 現行クラス能力をすべて破棄する前提には **しない**。
- 現行能力はある程度継承しつつ、Stage 先行で導出した必要能力を既存兵科へ **統合** する。
- ただし、現行クラス能力だけで実現可能かどうかを、敵問題や Wave 間関係の **採否基準にしない**。
- 具体的な統合判断は **R12e〜g**。

### 17.13 作戦全体として成立しない代表例

次は作戦全体の敵問題として扱わない。

- Wave ごとに敵編成が違うだけで、戦術要求の **関係** がない
- 各 Wave が独立問題で、作戦全体としての **判断** がない
- 編成変更可能だが、変更する **理由** が存在しない
- 作戦ポイントをどこへ使っても結果が **ほぼ同じ**
- 最終 Wave が過去 Wave と **無関係** な新問題
- 最終 Wave が敵数または scale を増やした **だけ**
- 全 Stage を同じ編成で処理できる
- 反対に、各 Wave で **必ず** 編成変更しなければならないことを機械的条件にする
- 戦術目標を UI 文として **直接正解表示** する
- 現行クラスで実現できないことを理由に、必要な問題構造を **除外** する

## 18. 試作 Stage の敵問題（R12d）

本節は [§15](#15-敵問題と戦術目標r12a) / [§16](#16-1-wave-単位の敵問題r12b) / [§17](#17-作戦全体の敵問題r12c) の枠組みに沿い、R12 縦切り用の **試作 Stage 1 本** の敵問題を具体化する。実装 API・JSON・Stage ID・数値バランス・能力の正式分配は定義しない。

必要能力・対処能力の導出は [§19](#19-必要能力対処能力r12e)。兵科・CombatModule・作戦内パッシブへの分配は [§20](#20-必要能力の兵科combatmodule作戦内パッシブ分配r12f)（**R12f 完了**）。

### 18.1 試作 Stage の位置づけ

- R12 の縦切りを成立させるための **試作 Stage は 1 本のみ** とする。複数 Stage は作らない。
- 本 Stage を R12e〜j まで縦に通し、ゲームとして成立するか確認する。
- 既存 `r10_prototype` を流用するか、後継 Stage へ置換するかは **後続実装で判断** する。本節では JSON や既存 Stage ID を確定しない。

### 18.2 作戦全体の中心判断

この Stage でプレイヤーに考えさせる中心判断は次である。

> 一点へ集中して保護構造を突破する能力と、複数の圧力へ戦力を分担する能力を、3 Wave を通してどう配分するか。

### 18.3 Wave 数

**3 Wave** 構成とする。

| Wave | 提示する問題 |
| ---- | ------------ |
| Wave 1 | 保護問題を単独提示 |
| Wave 2 | 分担問題を単独提示 |
| Wave 3 | Wave 1 と Wave 2 の要求を統合した複合問題 |

Wave 数が多いこと自体を難度条件にはしない（[§17.4](#174-wave-数の扱い)）。

### 18.4 Wave 1 — 保護問題

#### 敵編成

| 敵 | 配置 | 問題上の役割 |
| -- | ---- | ------------ |
| 鉄衛士 | 前衛 | 遮断型保護役 |
| 療養師 | 後衛 | 維持型保護役 |
| 魔術師 | 後衛 | 継続圧力を担当する中核役 |

#### 敵側戦術

- **主分類:** 保護（[§16.6](#166-敵側戦術の基本分類)）
- **補助構造:** 鉄衛士と療養師による役割分担

#### 構造

- 鉄衛士は既存の対象選択・前衛配置を利用し、通常の攻撃経路を自身へ向けさせる
- 専用のダメージ肩代わりや完全無敵は前提にしない
- 療養師は鉄衛士を優先して維持する
- 鉄衛士撃破後は魔術師の維持へ移る
- 魔術師は味方複数へ継続圧力を与え、処理期限を作る

本節の「継続圧力」は、DoT スタックや時間強化を意味しない。鉄衛士の RES は 0 である前提を置く。魔術師の RES 無視は前提にしない。

#### 戦術目標

> 味方全体が継続圧力で立て直し不能になる前に、遮断型または維持型のどちらかを先に処理し、保護構造へ突破口を作ったうえで中核を処理する。

これは [§5.3.1](#531-wave-勝利条件r12a) の勝利条件（敵全滅）の言い換えではない。

#### 通常解 A：鉄衛士先行

1. 療養師の維持を受ける鉄衛士へ集中する
2. 鉄衛士を突破する
3. 療養師の維持を受ける魔術師を処理する

要求：高耐久対象への継続処理、維持を上回る処理力、突破後の中核決定力。

#### 通常解 B：療養師先行

1. 鉄衛士を越えて療養師へ到達する
2. 維持機能を除去する
3. 鉄衛士と魔術師を順に処理する

要求：支援役への到達、鉄衛士を残したまま魔術師圧力を耐える能力、長期的な安定性。

#### 不成立

- 鉄衛士から倒す唯一解
- 療養師から倒す唯一解
- 3 体を均等に削るだけが最適
- 魔術師へ単純集中するだけで勝てる
- 全体攻撃で敵関係を無視できる
- 鉄衛士撃破時点で実質勝利になる
- 療養師を狙える兵科 1 体だけで問題全体が自動解決する

### 18.5 Wave 2 — 分担問題

#### 敵編成

| 敵 | 配置 | 問題上の役割 |
| -- | ---- | ------------ |
| 双刃士 | 前衛 | 即応要求型 |
| 魔術師 | 後衛 | 累積圧力型 |

双刃士は背後移動・低 HP 優先を持つため、単純な前衛順処理にはしない。双刃士に HP 吸収がある前提は置かない。

#### 敵側戦術

- **主分類:** 分担
- **補足:** 軽い相互作用を持つ

#### 構造

- 双刃士は低 HP 対象を狙い、早期脱落を発生させる
- 魔術師は味方複数へ継続圧力を与える
- 魔術師が味方を削るほど、双刃士が狙える対象が増える
- ただし、一方を処理すればもう一方が自動停止する **完全相乗にはしない**

本節の「累積圧力」は、DoT スタックや時間強化を意味しない。

#### 戦術目標

1. 双刃士が早期脱落を起こす前に、処理または抑制する
2. 魔術師の累積被害が決定的になる前に、処理する

両目標は戦闘開始時から同時に存在する。

#### 通常解 A：双刃士先行

1. 双刃士を短時間で処理する
2. 魔術師へ切り替える
3. 累積圧力が限界になる前に処理する

#### 通常解 B：双刃士を抑えて魔術師先行

1. 双刃士の早期圧力を耐久・回復・防護で抑える
2. 魔術師へ集中する
3. 累積被害源を先に除去する
4. 双刃士を処理する

#### 通常解 C：並行処理

- 一部を双刃士へ、一部を魔術師へ振り分ける
- 双方の期限を同時管理する

#### Wave 1 との関係

- **転換**
- **対立**

Wave 1 では、一方へ集中して突破口を作ることが有効だった。Wave 2 では、一方へ集中し続けると別の圧力が敗因になる。

中心判断は「集中するか分散するか」ではなく、次である。

> どこまで集中し、いつ対象を切り替えるか

#### 不成立

- 双刃士を無視しても問題にならない
- 魔術師を無視しても問題にならない
- 全体攻撃だけで 2 体を均等処理するのが最適
- 片方を処理すると他方も実質無力化される
- 単なる 2 体の火力チェック

### 18.6 Wave 3 — 複合問題

#### 敵編成

| 敵 | 配置 | 問題上の役割 |
| -- | ---- | ------------ |
| 鉄衛士 | 前衛 | 遮断型保護役 |
| 双刃士 | 前衛 | 即応要求型 |
| 療養師 | 後衛 | 維持型保護役 |
| 魔術師 | 後衛 | 累積圧力を担当する中核役 |

既存の前衛・後衛・射程配置を利用する。

#### 敵側戦術

- 保護
- 分担
- 相乗

ただし中心は、Wave 1 と Wave 2 を統合した **複合問題** である。

#### 構造

- 鉄衛士が通常経路を遮断する
- 療養師が鉄衛士を維持する
- 鉄衛士撃破後は魔術師を維持する
- 魔術師が味方複数へ累積圧力を与える
- 双刃士が低 HP 対象へ即応圧力を与える
- 魔術師の累積被害が双刃士の処理対象を増やす

#### 戦術目標

1. 双刃士の即応圧力を処理または抑制する
2. 鉄衛士または療養師のどちらかから保護構造へ突破口を作る
3. 魔術師の累積圧力が決定的になる前に中核を処理する

#### 双刃士の扱い

双刃士は撃破必須にはしない。

| 区分 | 内容 |
| ---- | ---- |
| 成立する対処 | 早期撃破 / 一部戦力で継続抑制 / 序盤だけ抑制し途中から中核へ集中 / 魔術師処理後まで残す |
| 不成立 | 完全放置 / 実質無害化 / 必ず最初に倒す一本道 |

#### 通常解 A：双刃士処理後の正面突破

1. 双刃士を早期処理する
2. 鉄衛士を突破する
3. 維持下の魔術師を処理する

#### 通常解 B：双刃士を抑えながら安定攻略

1. 一部戦力で双刃士を抑制する
2. 療養師を先に処理する
3. 鉄衛士を処理する
4. 魔術師を処理する

#### 通常解 C：短期抑制から中核突破

1. 双刃士を序盤のみ抑制する
2. 鉄衛士を突破する
3. 魔術師へ集中する
4. 残敵を処理する

#### 高度な別解

同一編成で全 Wave を攻略することは許容する（[§17.11](#1711-万能編成と作戦内汎用編成)）。

ただし必要条件：

- Wave ごとの戦闘方式変更
- 作戦ポイントの厳密な配分
- 複数用途を担う兵科
- 対象切り替え時点の精度
- 各 Wave 特化編成より小さい余裕

同一編成通しを、最も簡単な通常解にはしない。

#### 不成立

- 敵 4 体を全体攻撃で均等に削る
- 双刃士を無視できる
- 鉄衛士を無視して魔術師へ単純集中できる
- 鉄衛士撃破後は自動勝利
- 療養師先行だけが唯一解
- Wave 1・2 の理解を使わず、高火力だけで突破できる
- 敵数増加や scale 増加だけで難度を作る

### 18.7 Wave 間関係

| 接続 | 関係 |
| ---- | ---- |
| Wave 1 → Wave 2 | 転換＋対立 |
| Wave 1・2 → Wave 3 | 複合＋継続＋対立 |

根拠は [§17.3](#173-wave-間関係)。

### 18.8 作戦ポイントの判断構造

各 Wave の準備資源は `waves[].prepResourceGrant` で接続する（[§6.4](#64-wave-準備資源r12h)）。具体量・コスト・`grant`・`stackStep` は決めない（→ **R12i**）。

#### Wave 1 クリア後

| 選択方向 | 代償 |
| -------- | ---- |
| 双刃士への即応処理を強める | 即応特化は分担・保護突破が弱くなる |
| 双刃士を抑えながら魔術師へ対応する分担能力を強める | 分担特化は個別対象への決定力が弱くなる |

#### Wave 2 クリア後

| 選択方向 | 代償 |
| -------- | ---- |
| 鉄衛士または療養師への保護突破を深掘りする | 保護突破特化は初動事故が増える |
| 双刃士抑制と複数目標対応を維持する | 分担維持は中核への到達が遅れる |

### 18.9 通常解の位置づけ

次をいずれも許容する。各 Wave で必ず編成変更することを条件にしない。

- Wave ごとに 4 枠を変更する解
- 1〜2 枠だけ変更する解
- 編成を維持し、方式・作戦ポイントで補う解
- 同一編成通しの高度な別解

### 18.10 R12d 成立条件

本試作 Stage は、次をすべて満たす。

1. 各 Wave に敵側戦術がある
2. 戦術目標が勝利条件の言い換えではない
3. Wave 間に転換・対立・複合がある
4. 最終 Wave が過去 Wave の戦術要求を統合している
5. 敵数や scale 増加だけではない
6. 複数の通常解がある
7. 敗因を戦術目標単位で識別できる
8. 全 Stage 共通の万能編成を前提にしない
9. 特定 Stage 内の同一編成攻略を禁止しない
10. 現行クラス特性を利用しつつ、現行数値だけに設計を制約していない

## 19. 必要能力・対処能力（R12e）

本節は [§18](#18-試作stageの敵問題r12d) で確定した試作 Stage を成立させるために、プレイヤー側に必要な能力を導出する。

この段階では、CombatModule・作戦内パッシブへの正式分配は行わない。既存クラスとの対応は実装可能性の参考としてのみ記述する。正式担当は [§20](#20-必要能力の兵科combatmodule作戦内パッシブ分配r12f)（**R12f 完了**）。

### 19.1 能力の 4 層

| 層 | 内容 |
| -- | ---- |
| 処理能力 | 敵を倒す、削る、特定対象へ集中する |
| 到達能力 | 対象選択・射程・移動等により狙った敵へ届く |
| 抑制能力 | 撃破せず、一定時間敵の圧力を管理する |
| 維持能力 | 味方が敵問題を処理するまで戦線を保つ |

### 19.2 能力カテゴリ

#### A. 高耐久突破

> 前方の高耐久対象へ処理を集中し、維持を受けていても期限内に突破する能力。

必要要素：高耐久対象への継続処理 / 維持を上回る処理 / 防御特性へ強い処理 / 突破後も中核処理へ役割を移せること。

| 必須区分 | 内容 |
| -------- | ---- |
| 条件付き必須 | 支援役先行による迂回で代替可能 |

#### B1. 支援役到達

> 前方の遮断役を越え、敵の維持・防護を担当する支援役へ処理を届ける能力。

| 項目 | 内容 |
| ---- | ---- |
| 既存クラス上の主担当候補 | 双刃士（暫定記録。正式は §20） |
| 主な対象 | 療養師 |
| 必要要素 | 前衛に吸われにくい / 支援役へ届く / 支援役処理後に役割を失わない / 鉄衛士を残す代償を受け入れる |
| 必須区分 | 高耐久突破との **選択条件**。単独では無条件必須にしない |

制約：支援役到達だけで魔術師まで最適処理しない。後衛全体への万能到達にしない。

#### B2. 攻撃中核到達

> 前方の敵に吸われず、後方の攻撃中核へ継続処理を届ける能力。

| 項目 | 内容 |
| ---- | ---- |
| 既存クラス上の主担当候補 | 弓術士（暫定記録。正式は §20） |
| 主な対象 | 魔術師 |
| 必要要素 | 後方攻撃役への到達 / 継続的な処理 / 双刃士を残した状態でも役割を持てる / 鉄衛士への正面突破とは異なる強み |
| 必須区分 | **必須**。編成全体で少なくとも 1 経路 |

制約：療養師処理まで最適にならない。遠隔敵すべてを自動処理する万能枠にしない。

#### C. 即応処理

> 戦闘開始後の短時間で、高脅威対象へ有効な処理を集中する能力。

主な対象：双刃士。

必要要素：初動 / 短時間集中 / 対象切り替え速度 / 低耐久または高脅威対象への処理。

| 必須区分 | 内容 |
| -------- | ---- |
| 条件付き必須 | 抑制で代替可能 |

制約：高耐久突破にも同時に最適にしない。

#### D. 抑制

> 敵を倒さず、別の戦術目標を処理する時間を確保する能力。

成立形：攻撃を受け止める / 低 HP 対象を作らない / 即時回復 / Barrier / 被害軽減 / 回避 / 行動効率低下 / 通常行動阻害。

| 必須区分 | 内容 |
| -------- | ---- |
| 条件付き必須 | 即応処理とのどちらかは必須 |

制約：完全無力化にしない。担当枠の拘束、他目標への処理低下、抑制失敗の危険、継続的な維持コストがある。Barrier は HP 同様に処理されるため、Hit 数だけを Barrier 対策にしない。

#### E. 複数対象耐久

> 魔術師による複数対象への継続圧力を一定時間受けながら、他の戦術目標を処理する能力。

成立形：複数対象回復 / 継続回復 / 複数対象 Barrier / 魔法被害軽減 / 被害平準化 / 予防的耐久 / 魔術師の早期処理。

| 必須区分 | 内容 |
| -------- | ---- |
| 必須 | — |

制約：単体回復だけで完全対応させない。魔術師早期処理だけにも依存させない。Wave 1 では魔術師が保護されるため、一定時間耐える必要がある。

#### F. 中核決定力

> 保護構造を崩した後、主要な圧力源を期限内に処理する能力。

主な対象：魔術師。

必要要素：単一対象への高処理 / 後方への集中処理 / 保護解除後の決着速度 / 維持役が残る場合の対応力。

| 必須区分 | 内容 |
| -------- | ---- |
| 必須 | — |

高耐久突破との違い：

| 能力 | 焦点 |
| ---- | ---- |
| 高耐久突破 | 前衛・維持対象を処理する |
| 中核決定力 | 突破後の主要圧力源を処理する |

#### G. 分担・切り替え

> 異なる敵へ異なる役割を割り当て、Wave または戦闘中に担当を移す能力。

成立形：兵科ごとの固定優先対象 / 戦闘方式による対象数・射程・形状変更 / 編成変更 / 一方を抑制し一方を撃破 / 対象撃破後の役割移行 / 作戦ポイントによる担当強化。

| 必須区分 | 内容 |
| -------- | ---- |
| 必須 | この Stage の中心能力 |

不成立：全員が同じ対象へ集中 / 全員が最近傍だけを狙う / 全体攻撃が常に最適 / 対象撃破後に役割を失う / Wave ごとに編成を変えても挙動差がない。

### 19.3 必須能力の整理

#### 無条件に必須

- 攻撃中核到達（B2）
- 複数対象耐久（E）
- 中核決定力（F）
- 分担・切り替え（G）

#### 条件付き必須

| 対象 | 代替関係 |
| ---- | -------- |
| 鉄衛士対応 | 高耐久突破（A）**または** 支援役到達（B1）による迂回 |
| 双刃士対応 | 即応処理（C）**または** 抑制（D） |

#### 補助能力

次は補助であり、すべてを必須にしない。

- 高 DEF 優先
- 支援役優先
- 遠隔優先
- 低 HP 優先
- 魔法被害軽減
- 複数回復
- Barrier
- 防御無視
- 回復阻害
- 行動阻害
- 対象切り替え高速化

### 19.4 能力間の重複制限

次を **1 能力または 1 方式だけで完全に満たさない** 方針とする。完全排他ではない。同じ兵科・同じ方式がすべての問題へ最適になることを避ける。

- 高耐久突破＋即応処理
- 支援役到達＋攻撃中核到達
- 後方到達＋全対象への高火力
- 抑制＋高火力
- 複数対象耐久＋完全防護
- 分担能力＋高い全体攻撃
- 中核決定力＋すべての対象への汎用火力

### 19.5 能力セット

#### 能力セット A：正面突破型

| 含む能力 | 高耐久突破 / 中核決定力 / 複数対象耐久 / 双刃士への即応処理 / 最低限の攻撃中核到達 |
| -------- | ---- |
| 得意 | Wave 1 の鉄衛士先行 / Wave 3 の双刃士処理後の正面突破 |

| -------- | ---- |

8. 単一万能能力を作らない制約がある
9. 能力セットごとの強みと代償がある

## 20. 必要能力の兵科・CombatModule・作戦内パッシブ分配（R12f）

本節は [§19](#19-必要能力対処能力r12e) の A〜G を、試作 Stage 対象 **8 兵科** の兵科本体 / CombatModule / 作戦内パッシブへ分配する正本である。兵科ごとの固定役割・方式・パッシブ詳細は [classes-and-skills.md §R12f](classes-and-skills.md#r12f--必要能力の分配確定) を正とする。

**対象 8 兵科のみ:** `df_guardian` / `df_paladin` / `at_swordsman` / `at_assassin` / `at_ranger` / `at_sorcerer` / `sp_cleric` / `sp_wardweaver`。全兵科の詳細再設計には広げない。

**維持する上位分類:** Kill / Flow / Survival。A〜G は新しいロール分類ではなく、試作 Stage を解く能力カテゴリとしてこの上に重ねる。

- Kill 兵科を Survival 化しない / Survival 兵科を Kill 化しない
- Passive で固定優先ターゲットを変更しない / 兵科分類を反転させない
- 今回対象外の Flow 兵科領域を侵食しない

### 20.1 A〜G 主担当・副担当

| 能力 | 必須区分 | 主担当 | 副担当・補助 | 兵科本体 | CombatModule | 作戦内 Passive | 明確に外す対象 | 代償 |
| ---- | -------- | ------ | ------------ | -------- | ------------ | ------------- | -------------- | ---- |
| A 高耐久突破 | 条件付き必須 | 剣術士 | 魔術師は属性上の代替出力 | 高 DEF 優先、限定的 DEF 無視、前線耐久 | 高 DEF への集中処理 / 前線への処理分担 | 継続処理、被弾中の安定、撃破後移行 | 双刃士、弓術士 | 後方到達と複数圧力対応が弱い |
| B1 支援役到達 | 条件付き必須 | 双刃士 M1 | 原則なし | 現在 HP 最低優先 | 前線越境侵入 / 前線を越えない中距離仕留め | 侵入成功率、撃破後移行 | 弓術士、剣術士 | 敵魔術師の迎撃を受け、長期集中に弱い |
| B2 攻撃中核到達 | 無条件必須 | 弓術士 | なし | 遠隔攻撃役優先 | 単一中核集中 / 複数中核分担 | 集中維持、撃破後移行 | 双刃士、剣術士、魔術師 | 支援役と前線処理を放置する |
| C 即応処理 | 条件付き必須 | 魔術師 M1 | 剣術士 M2、双刃士 M2 は状況依存の補助 | 最近傍への魔法攻撃 | 単体即応 / 少数分散 | 初動・主対象への継続補強 | 弓術士、支援兵科 | 単体と複数を同時最大化できない |
| D 抑制 | 条件付き必須 | 護法士 M2、療養師 M1、結界師 M1 | 鉄衛士は追加 Passive 取得時のみ限定補完 | 軽減・回復・Barrier という別手段 | 危険対象防護 / 緊急回復 / 重点 Barrier | 各手段の条件付き補強 | 攻撃兵科、鉄衛士本体 | 攻撃枠と処理速度を失う |
| E 複数対象耐久 | 無条件必須 | 護法士 M1、療養師 M2、結界師 M2 | 鉄衛士は自分への支援要求を減らす間接寄与のみ | 軽減・復元・予防を分離 | 前線防護 / 分散回復 / 分散 Barrier | 方式深掘り、隣接補完 | 攻撃兵科 | 単体救命、長期復元、初動防護のどれかが不足 |
| F 中核決定力 | 無条件必須 | 弓術士 M1 | 剣術士は突破後、魔術師は露出後 | 中核へ届く固定優先、または条件成立後の単体処理 | 集中決着 / 分担処理 | 維持下の中核処理 | 双刃士を主担当にしない | 到達と決定力の両立に枠・投資が必要 |
| G 分担・切り替え | 無条件必須 | 編成全体 | 全兵科 | 固定優先ターゲット | 集中 / 分散、侵入 / 非侵入、重点 / 広域 | 専門化または最低限兼任 | 単一兵科、全体攻撃だけ | 集中時は別圧力が残り、分散時は決定力が落ちる |

**重要:**

- 魔術師は **B2 を担当しない**。前線突破後・露出後にのみ F へ参加できる
- 鉄衛士は **E の直接担当として数えない**（自己完結による間接寄与のみ）
- **D / E は兵科単位ではなく Module 単位**で担当が変わる

| Wave 3 | 剣術士・弓術士・魔術師による正面分担 / 双刃士 M1・弓術士による後方分担 / 鉄衛士の自己完結を利用した支援資源再配分 / 護法士中心の安定処理 |

複数解は維持される。

### 20.5 直接ダメージ（上位概念）

鉄衛士 M2（不屈型）の前提として、次の上位概念を記録する。**TypeScript 型・schema・combat.md への詳細編入は今回行わない**（→ 戦闘仕様への反映は保留。必要になったら [combat.md](combat.md) へ正本化する）。

#### 直接ダメージ（設計用語）

Attack 内の Hit として、攻撃者から対象へ直接適用されるダメージ。

| 含む | 通常攻撃 Hit、CombatModule による Hit、MultiHit の各 Hit、MultiLock の各対象 Hit、範囲攻撃の各命中、projectile 経由でも Attack の命中結果であれば含む |
| ---- | ---- |
| 含まない | DoT / 周期ダメージ、反射、自傷、環境ダメージ、遅延状態ダメージ、作戦ルール由来の独立ダメージ |

プレイヤー向け・設計上は「直接ダメージ」と表現してよい。内部データでは将来、Attack Hit / Triggered Hit / Periodic Damage / Environmental Damage / Self Damage / Reflected Damage 等へ細分できる余地を残す。

#### 鉄衛士 M2 のトリガー（より狭い定義）

上位の直接ダメージ全般ではなく、

> **敵の Attack Hit によって実際に HP ダメージが発生した各 Hit**

- 物理・魔法どちらでも発動可能
- DoT、周期ダメージ、反射、自傷、環境ダメージは対象外
- Barrier だけが削れた Hit、HP ダメージ 0 の Hit は対象外

現行 effect schema で表現できるかは未接続。**R12g** でデータ形状と後続実装先を判断する。production 実装は今回行わない。
